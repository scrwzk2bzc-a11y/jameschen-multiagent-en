Four environment traps get named individually, because their errors look nothing alike despite being one family:

1. **UTC clock**: containers default to UTC; business baselines run +08:00. Every ts must come from `TZ=Asia/Shanghai date`, or the books will show "the event happened after its own record." Hardcoded timestamps (filled from memory) are the same family: a measured 22-second drift on this cluster was caught by reconciliation.
2. **GBK**: the Windows side defaults to GBK encoding, and pythonw without a console crashes on decode (two cases on 2026-11-18, booked in bug_log). Before reading Chinese files across shells, confirm the decode state first.
3. **The popup**: pythonw without a console + docker subprocess spawning a new window pops an empty console window onto the desktop. Fix the root cause in how it launches, not by killing processes.
4. **PATH missing /usr/bin**: when the container's PATH lacks /usr/bin:/bin, `python3` dies at 127. The posture: export PATH explicitly before exec, or use absolute paths throughout.

The core postures matter more than the table — three of them:

One, error text goes into the ledger verbatim; "I retried and it worked" may not erase the process — the next person hitting the same error needs the original text, not reassurance. Two, evidence before hands: run the `cat`/`stat`/`grep` trio before any modification, so the pre-change mtime and permissions are on the books and the fix is back-verifiable. Three, environment-class errors do not count as reject (quality counts); product-class ones count per channel — mixing them lets environment problems trip the brake line, which is exactly how §7's count authority is protected.

Conclusion of this section: pits do not decrease; they only become one line on a quick-reference table. Over two weeks our pits did not get fewer — what changed was the average handling time per pit, because each pit became a row in the table the very night it was solved, and whoever comes next looks the response up directly.

How to verify: grep any row's error text against bug_log.md by path and find its ledger line; each of the four named traps is backed by a dated bug_log entry.
